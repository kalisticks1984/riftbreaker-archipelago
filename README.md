# The Riftbreaker - Archipelago

An Archipelago integration for The Riftbreaker's **open campaign**. It has two halves:

| Part | Path | Output |
|---|---|---|
| Game mod (Lua + data overrides, the game's local mod loader) | `mod/` | `mods/Archipelago/` in the game folder |
| AP world (Python, with the client) | `apworld/riftbreaker/` | `riftbreaker.apworld` |
| Shared data | `apworld/riftbreaker/data.json`, `mod/lua/archipelago/ap_data.lua` (generated by `tools/gen_open.py`) | read by both halves |

## Build

```
python -I tools/extract_data.py "<Riftbreaker>" <data_dir>   # research tree, campaign graph, difficulties, localization
python -I tools/gen_open.py <data_dir> .                     # mod data overrides + data.json + ap_data.lua
python -I tools/build.py --release --install                 # dist/, RiftbreakerAP-<version>.zip, install locally
```

IDs are `7720000 + node index in research_tree_open_campaign.rt` for research, `+1100+i` for biomes, `+1200+i`
for filler and `+2000+i` for progressive groups. They are stable for a given game version. Regenerate only after a
game update changes the tree.

## What it changes

| Feature | How |
|---|---|
| Checks | Every research node except the 11 free starting nodes (471). The mod polls `PlayerService:IsResearchUnlocked` and logs `[AP] CHECK <id>` |
| Rewards become items | `research_awards` stripped from those nodes in `research_tree_open_campaign.rt`; items arrive via `PlayerService:AddGlobalAward` |
| Progressive items | `<base>_lvl<N>` families (plus a bare `<base>` node as level 1): 62 groups; copy k grants level k |
| Biome items | The open campaign's auto-unlock chain (`logic_or_2 -> logic_wait_1` in `open_campaign_main.logic`) is cut. Biome items call `CampaignService:UnlockBiome` |
| Research labels | The client scouts every location on connect and writes `mods/Archipelago/gui/archipelago_localizations.csv` (item, receiver, classification). The game reads it at startup |
| Near-instant research | `reserach_science_factor` ("Research time factor", default 1) set to 0.01 on every `DifficultyDef`; costs unchanged |
| Goal | Campaign data `global.arcology_assembly_complete` or `global.prime_rift_complete` == "true" |

## Bridge (no networking in the game's Lua)

| Direction | Channel |
|---|---|
| game -> client | `Documents/The Riftbreaker/exor_logs.txt`, lines `[AP] HELLO / BOUND / MISMATCH / CHECKS / CHECK / GOAL / RECEIVED` |
| client -> game | `<game>/archipelago/inbox.lua` (`return { session, connected, player, items, labels }`), read with `loadfile` every 2 s |

A campaign is bound to the first `<seed>:<slot>` that connects (campaign data `archipelago.session`). Other slots get
`MISMATCH` and nothing is applied.

## Game facts this depends on (verified against the game binary)

- Local mods must be **folders** in `<game>/mods/`. `Exor::ExternalContentUserMods` mounts `.zip` files too, but only
  reads a `*.manifest` (keys `author`, `homepage`, `version`, `game_version`, `tags`) from folders. Zipped local mods
  show as "unknown" / incompatible.
- `lua/*_autoexec.lua` runs at startup; `is_server`, `RegisterGlobalEventHandler`, `MissionService:AddGameRule` work there.
- Research is enabled only while the player owns a building with `limit_name "communications_hub"` (native
  `IsResearchEnabled`). The `ap_hub` console command places one for testing.
- Lua 5.1 with `io`/`os` removed; `loadfile` reads real paths relative to `bin/` and re-reads changed files.
- Archipelago 0.6.7's `CommonContext` never sets `seed_name`; the client takes it from `RoomInfo`.
